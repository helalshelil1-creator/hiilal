# تأمين Firebase لموقع hiilal — خطوات التفعيل

المشروع: `hilal-web-1dfe4`

## الوضع الحالي (الخطر)

قاعدة Firestore كانت مفتوحة للقراءة **والكتابة** لأي شخص على الإنترنت بدون
تسجيل دخول. أي زائر يقدر يضيف أو يغيّر أو يمسح محتوى الموقع السحابي
(المحتوى، الأكواد، المواصفات، المنتجات، المشاريع، الفيديوهات، البرامج).
لوحة الإدارة الحالية محمية بكلمة سر في المتصفح فقط، وهي لا تمنع الوصول
المباشر لقاعدة البيانات.

## ما تم تجهيزه (لم يُفعّل بعد)

- `firebase/firestore.rules.secure` — قواعد تمنع الكتابة إلا لمدير مسجّل دخوله.
- `scripts/firestore-backup.js` / `scripts/firestore-restore.js` — نسخ احتياطي
  واستعادة لكل المجموعات.
- باقي خطوة دمج تسجيل الدخول في `admin.html` (أسفل).

## خطوات التفعيل (تحتاج حساب جوجل المالك للمشروع)

1. **نسخة احتياطية أولاً** — حتى وقاعدة شبه فاضية، خذ نسخة:
   `node scripts/firestore-backup.js` (التعليمات في رأس الملف).
2. **تفعيل Firebase Auth**: من لوحة Firebase → Authentication → Sign-in method
   → فعّل Email/Password. أنشئ مستخدمًا واحدًا للمدير بكلمة سر جديدة قوية.
3. **علّم المستخدم كمدير** (Variant A في القواعد):
   `admin.auth().setCustomUserClaims(uid, { admin: true })` من سكربت Admin SDK.
4. **انشر القواعد**: من لوحة Firestore → Rules → الصق محتوى
   `firebase/firestore.rules.secure` → Publish.
5. **حدّ من مفتاح الـ API**: Google Cloud Console → Credentials → قيّد المفتاح
   بنطاق الموقع (HTTP referrers) حتى لا يُستخدم من مواقع أخرى.
6. **غيّر كلمة سر الإدارة القديمة**: القديمة موجودة في تاريخ المستودع العلني
   على GitHub — تعتبر مكشوفة مهما حدث. أي كلمة سر جديدة تُنشأ من مسار
   الخزنة (vault) وليس يدويًا.

## دمج تسجيل الدخول في لوحة الإدارة (admin.html)

البوابة الحالية (مقارنة SHA-256 في المتصفح) تُستبدل بـ:

1. إضافة `firebase-auth` إلى سكربتات Firebase الموجودة.
2. `onAuthStateChanged` يعرض اللوحة فقط بعد تسجيل دخول ناجح
   (`signInWithEmailAndPassword`).
3. زر خروج `signOut()`.
4. بعد نشر القواعد، أي عملية كتابة من زائر غير مسجّل سترفضها Firestore
   نفسها — الحماية الحقيقية هي القواعد، وليست شاشة الدخول.

## ملاحظات

- لا تنشر القواعد قبل إنشاء مستخدم المدير، وإلا توقفت مزامنة اللوحة حتى
  يُنشأ المستخدم (لا بيانات تُفقد، لكن الكتابة تتوقف).
- ملف `serviceAccountKey.json` لا يُرفع أبدًا للمستودع.
